# SalesDrive

Система геймификации отдела продаж для Bitrix24. Лабораторные работы по дисциплине МиСПИСИТ.

Стек: Node.js 22, NestJS 10, TypeScript, Handlebars, Bootstrap 5.3, PostgreSQL 16. Для работы с базой и автоматического применения миграций используется TypeORM 0.3.20.

## Функции и правила

SalesDrive помогает руководителю отдела продаж отслеживать активность сотрудников. Форма начисления имитирует поступление события из Bitrix24. Для регистрации события руководитель указывает сотрудника, тип события и уникальный ID в CRM.

| Событие | Начисление |
|---|---:|
| Звонок клиенту | 5 XP |
| Новый лид | 10 XP |
| Закрытая сделка | 50 XP |

- Сотрудник появляется в рейтинге после первого успешного начисления. Рейтинг сортируется по сумме опыта, каждые 100 XP повышают уровень на один.
- В карточке сотрудника видны уровень, прогресс до следующего уровня и история начислений. В версии 0.0.6 к начислению можно добавить комментарий длиной до 255 символов. Если поле пустое, в истории отображается «Без комментария». Такое же значение получают записи, созданные до обновления.
- Один ID события в CRM можно использовать только один раз. Если обязательное поле пропущено, данные некорректны или событие уже учтено, опыт не начисляется. Причина сохраняется в журнале отклонённых событий.
- После успешного начисления появляется уведомление. Если сотрудник достиг нового уровня, это указано в том же сообщении. Уведомления можно отметить прочитанными по одному или все сразу.
- На главной странице показаны версия приложения, количество сотрудников, начислений и отклонённых событий.

## Запуск

```text
Репозиторий: https://github.com/Donjkeeez0r/mispisit
Ветка: lab6
Pull Request: https://github.com/Donjkeeez0r/mispisit/pull/6
Образ: donjkeeez0r/mispisit-lab1:0.0.6

git clone -b lab5 https://github.com/Donjkeeez0r/mispisit
cd mispisit
docker compose up -d

git checkout lab6
docker compose up -d

docker compose run --rm backup
docker compose down -v
docker compose up -d db
docker compose run --rm restore
docker compose up -d
```

После первого блока откройте http://localhost:8080 и создайте начисление в версии 0.0.5. Запомните ID события в CRM.

После второго блока проверьте версию 0.0.6 на главной странице. Откройте карточку сотрудника через рейтинг и найдите прежнее начисление по ID. В столбце «Комментарий» должно отображаться «Без комментария».

Третий блок проверяет восстановление. Выполняйте команды по одной. После успешного создания копии команда `docker compose down -v` удаляет том учебной базы. После восстановления откройте карточку сотрудника и убедитесь, что начисление с тем же ID и комментарием вернулось.

## Страницы

| Адрес | Что на странице |
|---|---|
| http://localhost:8080/ | Главная: версия, сводка, переход к функциям |
| http://localhost:8080/leaderboard | Рейтинг отдела |
| http://localhost:8080/events/new | Форма начисления опыта за событие из CRM |
| http://localhost:8080/events/rejected | Отклонённые события |
| http://localhost:8080/notifications | Уведомления о начислении опыта (новые и прочитанные) |
| http://localhost:8080/employees/:id | Карточка сотрудника: уровень, прогресс и история начислений с комментариями. Открывается из рейтинга. |

Данные хранятся в PostgreSQL (сервис `db`, том `dbdata`).

## Резервная копия и восстановление

Команда `docker compose run --rm backup` создаёт полную логическую копию PostgreSQL в файле `backup/app.sql`. В неё входят данные приложения и история применённых миграций. При повторном запуске файл перезаписывается.

Команда `docker compose run --rm restore` восстанавливает базу из `backup/app.sql`. При восстановлении на чистом томе сначала запустите PostgreSQL командой `docker compose up -d db`. После успешного восстановления запустите приложение командой `docker compose up -d`.
